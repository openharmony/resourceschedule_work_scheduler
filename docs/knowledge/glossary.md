# 业务术语表

> 文档版本：v1.0
> 更新时间：2026-09-10

## 通用术语

**当前组件**：延迟任务调度/Work Scheduler，OpenHarmony 资源调度子系统的核心组件，负责在应用退至后台后为时效性要求不高的任务提供延迟调度能力。当应用满足设定的触发条件（包括网络类型、充电类型、存储状态、电池状态、定时状态等）时，将任务添加到执行队列，系统根据内存、功耗、设备温度、用户使用习惯等统一调度拉起应用执行。组件位于 `foundation/resourceschedule/work_scheduler` 目录下。

| 特性/功能中文名 | 特性/功能英文名 | 特性描述 |
|---|---|---|
| 延迟任务 | Work Scheduler | 为时效性要求不高的后台任务提供延迟调度能力，条件满足后系统统一调度拉起执行 |
| 后台预取器 | Background Loader | 面向应用的轻量级后台任务加载机制，通过 IPC 远程对象拉起 Ability 执行任务，支持超时监控和黑名单管理 |

## 延迟任务术语

| 中文名 | 英文名 | 描述 |
|---|---|---|
| 延迟任务ID | workId | 应用内唯一标识，必填，用于区分不同的延迟任务实例 |
| 任务条件 | WorkCondition::Type | 触发延迟任务执行的系统条件类型，包括网络、充电、电池状态、电量、存储、定时器、分组、深度空闲、待机 |
| 条件就绪 | Condition Ready | 任务的所有设定条件均已满足，进入待执行状态 |
| 条件队列 | WorkQueue | 按条件类型组织的任务队列，条件变化时计算就绪任务列表 |
| 就绪队列 | conditionReadyQueue_ | 条件满足后等待策略过滤与执行的队列 |
| 运行队列 | runningQueue | 通过策略过滤后正在执行的任务集合，受最大并发数约束 |
| 策略过滤 | Policy Filter | 根据电源模式、内存压力、热管理、CPU 占用等系统状态限制运行任务数 |
| 看门狗 | Watchdog | 任务执行超时监控器，超时后强制终止任务（默认 2 分钟） |
| 持久化任务 | persisted | 设备重启后自动恢复执行的延迟任务，存储于 JSON 文件 |
| 预安装任务 | preinstalled | 来自预安装配置文件的延迟任务 |
| 应用分组 | App Group | 根据应用活跃度对应用分组，不同分组有不同执行频率约束 |
| 深度空闲 | Deep Idle | 设备进入深度空闲状态（屏幕关闭超过一定时间） |
| 设备待机 | Device Standby | 设备进入待机模式，限制后台任务执行，部分应用可加入白名单豁免 |

## 后台预取器术语

| 中文名 | 英文名 | 描述 |
|---|---|---|
| 后台预取任务信息 | BackgroundLoaderTaskInfo | 后台预取任务参数，包含 taskId 和 abilityName |
| 任务状态 | TaskStatus | 后台预取任务状态枚举：未注册(-1)、未开始(0)、运行中(1)、已完成(2) |
| 停止码 | StopCode | 后台预取任务停止原因：成功(0)、系统错误(1)、可感知错误(2)、超时错误(3)、执行错误(4) |
| 超时计数 | timeoutCount | 后台预取任务超时次数计数，超过阈值后加入黑名单 |
